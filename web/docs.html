Reference

The API, in full.

ShadowGate speaks the OpenAI HTTP API. If a tool can call OpenAI, it can call ShadowGate — change the base URL and the key, nothing else.

Quickstart

  1. Open the console → Sessions → add a ChatGPT session (raw cookie or export JSON).
  2. API keys → create a key. Copy the sg-… value: it is shown once and stored as a hash.
  3. Point your client at /v1:
python
from openai import OpenAI

client = OpenAI(base_url="https://your-gate/v1", api_key="sg-••••")
r = client.chat.completions.create(
    model="gpt-5",
    messages=[{"role": "user", "content": "hello, shadow."}],
)
print(r.choices[0].message.content)

Authentication

Send your key as a bearer token on every request. Keys are stored server-side as SHA-256 hashes and can be disabled or deleted at any time from the console. Each key carries its own rpm (requests per minute) and rpd (requests per day) limits.

header
Authorization: Bearer sg-••••••••••••••••••••••••••••••••••••••••••••••••

Requests to /v1 accept any origin (CORS *): the API carries no cookies, so browser-based clients can call it directly with a key.

POST /v1/chat/completions

Creates a completion. The pool picks a healthy session, performs the sentinel handshake and proof-of-work, opens the conversation and translates the stream back into OpenAI's shape.

FieldTypeDescription
modelstringAny id from /v1/models or an alias; unknown names fall back to auto. See model mapping.
messagesarrayOpenAI-style messages. system / developer messages are honoured and history is preserved. Array content parts of type text are joined; images are ignored.
streambooleantrue → server-sent events in the chat.completion.chunk format.
reasoning_effortstringminimal / low / medium / high → the backend's thinking effort. See reasoning effort.
tools, tool_choicearrayOpenAI function calling, emulated. See function calling.
response_formatobjectjson_object / json_schema: the model is instructed to answer with bare JSON and fences are stripped (streams are delivered whole).
stop, max_tokens—Applied to the visible text (finish_reason becomes stop / length; tokens are estimated at 4 characters).
temperature, top_p, n, seed …—Accepted and ignored. ChatGPT's web backend does not expose sampling controls.
curl
curl https://your-gate/v1/chat/completions \
  -H "Authorization: Bearer sg-••••" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [{"role": "user", "content": "Summarise the Faust legend in one line."}]
  }'
response · 200
{
  "id": "chatcmpl-…",
  "object": "chat.completion",
  "created": 1760000000,
  "model": "gpt-5",
  "choices": [{ "index": 0, "message": { "role": "assistant", "content": "…" }, "finish_reason": "stop" }],

Token counts in usage are estimates (characters ÷ 4). ChatGPT's backend does not report exact usage.

Streaming

Set "stream": true. You receive text/event-stream frames identical to OpenAI's, ending with data: [DONE]. Every streaming client works unmodified. If the upstream stream is interrupted after output has started, the gateway appends a short bracketed note and closes the stream cleanly.

event stream
data: {"id":"chatcmpl-…","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant","content":""},"finish_reason":null}]}

data: {"id":"chatcmpl-…","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"Hel"},"finish_reason":null}]}

data: {"id":"chatcmpl-…","object":"chat.completion.chunk","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]

Reasoning models stream their thought summaries as delta.reasoning_content chunks before the answer (the DeepSeek / OpenRouter convention most chat clients render as a collapsible thinking block); in JSON mode the summary is returned as message.reasoning_content. Pass "stream_options": {"include_usage": true} to receive a final usage chunk before [DONE]. When the model runs code or tools on ChatGPT's side, only the visible answer is forwarded.

If the client disconnects mid-stream, the upstream conversation is aborted immediately so no quota is wasted. While a reasoning model thinks, the stream carries SSE comment lines every 15 s so idle-connection timeouts (Cloudflare's 100 s, for instance) never cut a long thought short — one more reason agents should stream.

Large inputs. ChatGPT's backend accepts about 480k characters of text per request (roughly 120k tokens) and about 330k in a single message, whatever the model's context window. ShadowGate splits an oversized message for the backend, and when a whole conversation outgrows the budget it compacts the history itself the way an agent harness would: older tool results and turns are clipped first, then the oldest turns are dropped; the system prompt, the first user message and the latest exchange are kept intact. If a single message is over budget on its own it is clipped head-and-tail around a marker that says how much was cut. A compacted request carries an x-shadowgate-compacted: before->after header; 413 is now only a last resort. context_length in /v1/models is the model's real context window as chatgpt.com reports it (262k for the GPT-6 family, 137k for GPT-5.6, 410k for Pro); request_budget_tokens is the per-request budget the gateway enforces by compaction (about 120k tokens of text). Images are uploaded as files and do not count against it.

Continuation. Agent harnesses resend the whole conversation every turn. When a request is the previous conversation plus new messages, ShadowGate sends only the new messages into the backend conversation it already has, instead of re-uploading the history: faster turns, and the per-request budget applies only to what is new. The response carries x-shadowgate-continued: N (messages sent). Anything that changes the history — an edit, a compaction, another model or effort — misses the cache and falls back to a full resend, which is always correct; a continuation the backend has lost is resent in full automatically. Plain models continue inside temporary chats (nothing is saved to the account). GPT-6 work-mode models can only continue a saved conversation, so with the default setting their conversations appear in the ChatGPT account's history while active and are hidden again after 25 minutes idle (and on shutdown). Settings → conversation continuation switches between all models, plain models only, or off.

Usage caps. When an account hits ChatGPT's usage cap for a model, the gateway remembers that for an hour and serves the same model from another session in the pool; 429 model_cap_reached only comes back when no session can serve it.

GET /v1/models

ShadowGate asks chatgpt.com which models each session's account may use and lists those real slugs (for example gpt-5-6, gpt-5-6-thinking, gpt-5-6-pro, gpt-5-6-mini), one row per real model, each with a title of its own (chatgpt.com calls the whole 5.6 family "GPT-5.6 Sol"; the listing says "GPT-5.6 Sol Instant", "GPT-5.6 Sol Thinking" and so on), its lane, its reasoning metadata, context window and input modalities. The response also carries default_model. Aliases are not listed, but GET /v1/models/{alias} (for example /v1/models/astra) returns the alias with its alias_of; an unknown id is 404. The catalog refreshes every time a session is verified.

A real slug is sent upstream unchanged (dots and dashes are interchangeable: gpt-5.6-thinking works). Anything else is an alias:

RequestedResolved to
auto, gpt-5, gpt-4o, gpt-4, unknownthe account's default (router) model
*thinking*, o1, o3, o4, or any model with reasoning_effort: highnewest reasoning model of that generation
*pro*newest Pro model of that generation
*mini*, *nano*, gpt-3.5newest mini (thinking-mini when combined with "thinking")
*instant*instant lane
astra, luna, sol, terra, gpt-6newest model with that codename / generation (astra → gpt-6-astra, sol → gpt-6.1-sol, gpt-6 → newest non-Pro GPT-6)

GPT-6 family. gpt-6-astra, gpt-6-luna, gpt-6-sol, gpt-6.1-sol (and the 5.6 codenames gpt-5.6-terra, gpt-5.6-luna, gpt-5.6-sol) are listed under those clean names. Upstream they exist only as work-mode slugs ending in -wm, served inside a work-mode conversation; ShadowGate sends that form automatically, the response's model shows the clean name, and the x-shadowgate-model header shows the exact upstream slug. Each row's upstream_slug says what is sent. Beware the echo trap: chatgpt.com accepts any slug (gpt-6-astra without the suffix, even gpt-9-zeus) and echoes it back as model_slug while quietly answering from the plan's fallback lane, so a bare name proves nothing — only the work-mode form reaches the real model. These models may describe themselves as "GPT-5" or "ChatGPT" when asked; trust the model field.

The model field in every response (and every stream chunk) is the slug the backend actually answered with, and the x-shadowgate-model response header shows the resolved slug plus effort. A model your plan cannot use returns 429 with the upstream message.

Images

Send images the OpenAI way — an image_url content part holding a data: URL or an http(s) URL (PNG, JPEG, GIF or WebP, up to 20 MB each). ShadowGate uploads each one to the account's file service exactly as chatgpt.com does and attaches it to the message, so the model sees the picture, not a description of it. Every listed model carries input_modalities: ["text", "image"]; the same image sent twice on one session is uploaded once.

image input
{ "model": "gpt-6-astra", "messages": [{ "role": "user", "content": [
    { "type": "text", "text": "What is in this screenshot?" },
    { "type": "image_url", "image_url": { "url": "data:image/png;base64,iVBORw0…" } } ] }] }

Function calling (emulated)

ChatGPT's backend has no native tool calling, so ShadowGate emulates OpenAI's: send tools (or legacy functions) and the model is briefed on them in a system preamble with a strict call format. When it wants to act, the reply arrives as real tool_calls (stream: delta.tool_calls chunks, finish_reason: "tool_calls"). Send the results back as tool messages with tool_call_id and the loop continues, exactly like the OpenAI API. tool_choice auto / required / none / a named function are honoured by instruction. Agent harnesses (OpenCode, Open Interpreter, custom loops) work unmodified.

The model also owns a sandbox on OpenAI's side (code execution, browsing). The preamble tells it that sandbox is not your machine and that only the functions reach you; it follows that reliably but not perfectly — if it reports a Linux path when you asked about your PC, it used its own sandbox. Tool calls work best with the thinking and GPT-6 models. When your harness offers no browsing or fetch tool, the model will browse with ChatGPT's own browser instead (slow, and invisible to you) — give it a fetch_url / web_search tool and it prefers yours. Link cards and citations in answers are forwarded as markdown links.

Reasoning effort

Send OpenAI's reasoning_effort (none / minimal / low / medium / high / xhigh) — or reasoning: {"effort": …}, or ChatGPT's own words standard / extended. ChatGPT's thinking models know exactly two efforts, so the OpenAI levels collapse onto them:

reasoning_effortthinking_effort sent
none, minimal, low, medium, standardstandard
high, xhigh, max, extendedextended

Discoverable. Every entry in /v1/models states its reasoning capability under the names harnesses look for: reasoning / supports_reasoning (boolean), reasoning_efforts (the OpenAI spellings the model accepts), reasoning_effort_map (what each becomes upstream), thinking_efforts (ChatGPT's own values), plus capabilities, input_modalities, max_output_tokens and limit. A harness that reads the listing can build its effort menu from it. Harnesses that only take declared levels per model — ZadLoop and the DeepSeek Harness among them — want the levels in their provider config; for an openai-completions route each model takes a reasoningEfforts map whose values are sent as reasoning_effort:

ZadLoop / DeepSeek Harness — cordis.patch.yml
providers:
  shadowgate:
    displayName: ShadowGate
    api: openai-completions
    baseURL: https://ai.shadowvpn.live/v1
    apiKeyEnv: SHADOWGATE_API_KEY
    models:
      - id: gpt-6-astra
        name: GPT-6 Astra
        contextWindow: 120000
        maxTokens: 16384
        input: [text]
        reasoningEfforts:
          low: standard
          high: extended

The menu then offers Default (the backend's own effort), Low and High. Pro models accept standard only, so they take no reasoningEfforts (or false).

extended thinking
{ "model": "gpt-5-thinking", "reasoning_effort": "high",
  "messages": [{ "role": "user", "content": "Prove it carefully." }] }

Asking for high on a non-reasoning alias such as gpt-5 upgrades the request to the thinking lane. Models without configurable effort ignore the field.

Errors

Errors are OpenAI-shaped: {"error": {"message", "type", "param": null, "code": null}}.

StatusTypeMeaning
400invalid_request_errorMalformed JSON or invalid messages.
401authentication_errorMissing or unknown API key.
403permission_errorKey disabled.
413invalid_request_errorBody over 24 MB, an image over 20 MB, or a conversation that cannot be compacted under the backend's budget.
429rate_limit_errorKey limit hit (retry-after set), or the ChatGPT plan's model cap was reached.
502upstream_errorChatGPT refused or dropped the conversation after retries across sessions.
503service_unavailableNo healthy sessions in the pool.

Rate limits

Per-key sliding windows: 120 requests / minute and 20 000 / day by default (agent loops make one request per tool round), editable per key in the console. When exceeded the gateway answers 429 with a retry-after header (seconds). GET /v1/models does not count against the limit.

Admin API

The console talks to /api/admin/* with a signed HttpOnly cookie and an x-csrf-token header on every mutation. It is not meant for third-party clients, but it is plain JSON if you want to script it:

EndpointPurpose
POST /api/admin/login · logout · GET sessionAuthenticate (username, password, optional totp) and read the CSRF token.
GET /api/admin/statsDashboard numbers: 24 h traffic, hourly buckets, model mix, top keys, pool health.
GET · POST · PATCH · DELETE /api/admin/keysAPI key CRUD. The full key is returned once on creation.
GET · POST · PATCH · DELETE /api/admin/tokens, POST …/:id/verifySession pool CRUD and on-demand verification.
GET /api/admin/logs · auditRequest log (filterable) and the admin audit trail.
GET · POST /api/admin/settings · password · totp/* · sessions/revokeConsole preferences and security.

Notes

  • Session tokens are personal credentials. Keep the gateway private: anyone holding an sg- key spends your ChatGPT quota.
  • When you paste a full session export, ShadowGate reuses the export's device id and user agent. This keeps anti-bot challenges away far better than a random fingerprint.
  • ShadowGate is not affiliated with OpenAI. Automating the ChatGPT web app may violate its terms of use; run it for yourself, with your own accounts.
