      How it works
      
Three moving parts. No magic.

    

    

      
      

        
01

        
Connect a session

        
Paste your __Secure-next-auth.session-token — or a full session export — into the console. ShadowGate verifies it, keeps its device identity, and stores it encrypted.

      

      

        
02

        
Mint a key

        
Create sg-… API keys with their own requests-per-minute and per-day limits. Keys are stored as SHA-256 hashes; the full value is shown exactly once.

      

      

        
03

        
Call it like OpenAI

        
POST /v1/chat/completions with your key as a bearer token. JSON or SSE. Every OpenAI SDK, CLI and plugin you already use works unmodified.

True token streaming

        
ChatGPT's event stream is translated live into chat.completion.chunk frames. First byte in milliseconds, clean [DONE] framing.

Session pool & rotation

        
Least-recently-used rotation across sessions, automatic access-token refresh, cooldown on throttling and a health check every ten minutes.

      

      

        

          
        

        
A console you'll actually open

        
Live dashboard, request logs, key and session management, audit trail — with real-time charts and nothing to install.

      

      

        

          

          
        

        
Hardened by default

        
Bcrypt logins with lockout, optional TOTP 2FA, signed HttpOnly sessions, CSRF double-submit, AES-256-GCM encrypted secrets, per-key limits, strict CSP. Every admin action is audited.

Express and bcryptjs. No telemetry. The only outbound connections go to chatgpt.com. Small enough to read in an afternoon.

      

    

  


  
  

    

      Threat model
      
Security is the product,
not a feature.

      
This thing guards live ChatGPT sessions. It is built to assume the disk leaks, the key leaks and someone is brute-forcing the login at 3 a.m.

    

    
    
      
  1. 01
    Secrets encrypted at rest
    Session and access tokens are AES-256-GCM encrypted with a key derived from SECRET_KEY. A stolen store.json is noise.
    2. 
      
  2. 02
    Keys you can't leak twice
    API keys are stored as SHA-256 hashes and displayed once. Disable or delete any key instantly from the console.
    3. 
      
  3. 03
    Logins that fight back
    bcrypt(12), five strikes and a fifteen-minute lockout per visitor, timing-flat comparisons, optional TOTP 2FA.
    4. 
      
  4. 04
    Sessions that can be revoked
    Signed HttpOnly SameSite=Strict cookies with a server-side version. One click signs out every console everywhere.
    5. 
      
  5. 05
    Browser-side defense in depth
    Strict Content-Security-Policy with no inline scripts, frame denial, nosniff, referrer policy and CSRF double-submit on every mutation.
    6. 
      
  6. 06
    Nothing leaves the box
    Visitor IPs are hashed in logs. There is no telemetry, no analytics, no phone-home. The only upstream is chatgpt.com.
    7.

from openai import OpenAI

client = OpenAI(base_url="https://your-gate/v1", api_key="sg-••••")
r = client.chat.completions.create(
    model="gpt-6-astra",
    messages=[{"role": "user", "content": "hello, shadow."}],
)
print(r.choices[0].message.content)

      
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "https://your-gate/v1", apiKey: "sg-••••" });
const r = await client.chat.completions.create({
  model: "gpt-6-astra",
  messages: [{ role: "user", content: "hello, shadow." }],
});
console.log(r.choices[0].message.content);

      
const stream = await client.chat.completions.create({
  model: "gpt-6-astra", stream: true,
  messages: [{ role: "user", content: "Stream me a haiku." }],
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}
// frames arrive as chat.completion.chunk and end with data: [DONE]
